# Production render ownership continuation

The shared orthographic renderer now writes each PNG in a fresh producer-owned run, verifies it, and publishes it atomically to its normal final name without clobbering an existing file. Fifteen focused real-filesystem/fake-Blender fixtures pass. The approved native cube canary also passed: exactly two 128×128 front frames, 6.674 seconds, peak process RSS 500,396,032 bytes, no fits, raw surface comparisons or qualification helpers. [render-evidence.json](render-evidence.json) retains actual source/receipt hashes, process bounds and both ownership audits.

The first native call returned `front.png`; the second returned `front_2.png`. The first file's bytes remained unchanged and decoded RGBA pixels were exactly equal across the two frames. Encoded PNG hashes differ, so the receipt binds each distinct file separately and does not claim identical encoded files. The cube's indexed geometry hash remained `f81a66bb82dd1c0e2c999a97b466225612291ab9bd826b8e8642ad7cc91b7d61`. Engine, image settings, resolution, sample settings and view settings were restored; scene filepath retained the actual last final output. Both manifests succeeded, both leases released, and both read-only ownership plans report `dry_run_ready` with no unknown files or blockers. The native interpreter was the already-authorized bundled Blender 5.2 Python; its exact `sys.executable` and `sys.prefix` are retained.

## Implementation and compatibility

- `blender_blocking/utils/artifact_publication.py` exposes `publish_file_no_clobber(staged, destination) -> Path`. It requires a regular, producer-owned immutable stage and calls `os.link`. A collision raises `FileExistsError`; other filesystem errors propagate. It performs no replacement, copying, deletion, directory creation or ownership inference.
- `blender_blocking/integration/blender_ops/render_utils.py` creates only new `.render-runs/owned-*` roots beneath the resolved output directory. The usual returned paths remain in the caller's output directory. Existing prefixes, indices, suffixes, long-name compaction, relative returned strings, view order, render settings and early unavailable/no-target exits are preserved. Publication collisions retry up to 128 times using the existing naming sequence, without another render.
- The legacy `render_orthogonal_views` API still returns its view-to-path dictionary. The detailed result adds an optional trailing `ownership_receipt` field; it appears in `to_dict` only when an owned attempt exists. Each receipt records stage/final paths, byte count, SHA256, view and publication state. Producer writes end before publication.
- Completed published stages remain `final_output`; partial or unpublished stages remain diagnostics. A render, validation, progress callback or publication failure retains prior completed final images and known new partials. Cancellation records a cancelled lease state. Secondary receipt errors annotate the original exception, with ownership metadata preserving its failure. The renderer starts no child process and closes ownership only after its synchronous render/session restoration returns.

The PNG allowance covers the requested count/dimensions and existing possible 16-bit RGBA depth, compression/filter overhead and four MiB of receipt headroom. It is reserved before rendering and checked against actual registered files afterward; it is not an operating-system disk quota. Unknown or changed files remain blocked by the existing ownership inspector rather than being adopted.

## Focused evidence and limits

`test_render_run_ownership.py` covers real competing publication attempts, existing-file preservation, unsupported/locked publication, default/prefixed/indexed/relative/compacted paths, collision retries, failed partials, PNG validation, progress failures, settings/filepath, cancellation, secondary diagnostic errors, unsupported views and early exits. Test-runner registration belongs to root. No broad Blender campaign was run.

Atomic publication requires hard-link support on the final filesystem; unsupported publication retains staging and fails explicitly. Stage and final names share file bytes: a later external edit can change them and will fail their recorded hash checks. No ACL change or security freeze is attempted. No final path is overwritten by this producer, no historical directory is adopted, and no files are reclaimed. The generic `save_render` exact-path overwrite helper remains unchanged and outside this adoption. Variant runner adoption belongs to the sibling task; backend export/cache/report ownership, descendant supervision, crash recovery and deletion remain separate work.

The earlier [proposal](proposal.md) records the original implementation design and wider variant boundaries. Current runtime working files retain their native-tested CRLF bytes; staged repository line-ending normalization does not require a fresh render.
