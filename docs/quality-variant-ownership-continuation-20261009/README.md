# Fresh refinement variant attempts

Production variant runners now create one fresh owner under the actual variant directory's `.variant-runs` only when an attempt executes. The existing cache/resume lookup remains ahead of attempt creation; a real local-resume hit created no new owner. Final render `r`, backend `a`, reference and cache paths are unchanged and remain external. There is no recursive directory adoption, cleanup, deletion or recovery implementation.

New command/config/log records and result transport live inside the fresh owner root. References, the E2E entrypoint and runner source are hashed as shared-input provenance. The completed result JSON is validated and atomically published through the shared hard-link primitive to `result.json` when free, otherwise `result_2.json` and subsequent suffixes. The returned `ExperimentResult.result_json` and `artifacts['result']` contain the actual published path. Old command/config/stdout/stderr aliases are preserved; a free alias can receive the first completed record. Fresh per-attempt records remain authoritative, including when an optional alias cannot be published. Both outer reference/config/execution error writers use the same staged publication policy. A failed quality verdict marks its attempt failed independently of successful result publication.

Subprocess execution uses `Popen`, explicit direct-child wait and continuous stdout/stderr drain threads. Each binary stream retains at most 32 KiB plus an 8 KiB read chunk and records its full byte count, truncation and drain error. The real noisy fixture wrote over 1 MiB to each stream; both retained files were exactly 32 KiB and included their ending markers. There is no variant `capture_output` buffer growing with total output. The existing git metadata helper is outside this variant-child transport change.

`RunOptions.variant_timeout_s=None` preserves the prior absence of an outer timeout. Explicit values must be numeric, finite and positive, excluding bool. On timeout/cancellation only the directly owned child is terminated and joined; a five-second wait can be followed by a kill of that same child and a second five-second wait. Each pipe drainer has a one-second completion wait. Unconfirmed child or pipe completion retains an active lease with diagnostic notes. Primary errors survive secondary log/receipt/publication errors. Spawn failures and joined failure outcomes release failed leases; receipt persistence failure can conservatively retain an active lease. The runner does not claim backend descendant ownership.

Fourteen focused ownership checks pass across recorded focused runs. They cover real tiny standard-library child success/failure, previous result/command/config/log byte preservation, 1 MiB two-stream draining, real timeout/cancellation, controlled unconfirmed join, launch/publication/invalid JSON, in-process result suffixes, both outer error writers, actual resume without a new owner, invalid timeout values, configuration failure diagnostics, retained primary cancellation on secondary receipt failure, competing result publication, legacy in-process signature retry, and optional alias failure with unchanged computation verdict. The combined run passed the initial thirteen ownership checks and all twenty-three existing refinement runner compatibility/cache/resume/path tests in 28.418 seconds. After the final alias handling change, the three affected failure/join tests passed in 2.365 seconds and the added optional-alias test passed in 0.941 seconds. There was no Blender variant campaign or GPU fixture.

Each fresh attempt has a 64 MiB registered-artifact bound. Result size is checked before JSON decoding. This is a producer artifact limit, not an operating-system disk quota; a misbehaving external child can write beyond it before registration rejects the attempt. No process RSS maximum was claimed or measured for these focused tests. Runtime and test text retain the existing Windows CRLF format.

Remaining scope is explicit: backend artifact overwrites under `a`, mutable report/index/cache outputs, full process-tree supervision, inherited-pipe descendant completion, crash recovery, cleanup and historical ownership adoption are unchanged. Atomic publication requires same-filesystem hard-link support and fails without a copy/replace fallback. No deferred native, recovery or cleanup command is supplied. Root owns test-runner registration and final integration; the shared publication utility and renderer are the canonical helper's separate deliverables.

[Evidence](evidence.json) records exact source identities and validation outcomes. All new stages and published hard links are retained by the production code.
